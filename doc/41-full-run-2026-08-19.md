# Full IH1 run after the fixes, and what it says about Gate C

`-rt_seed cirt -threads 96 -live_memory_gb 400 -gate_log`, our library
(4,991,901 targets + 4,625,804 decoys). Identical to the 14,167 baseline except
for the per-Session gate calibration (1143255) and the diagnostic log.

## Result: the fix is neutral-to-slightly-negative

| | baseline | this run | delta |
|---|---:|---:|---:|
| identifications at q <= 0.01 | 14,167 | **14,081** | **-86 (-0.6%)** |
| entrapment FDP | 11.76% | **12.36%** | +0.60 pp |
| DIA-NN truth recovered | 11,071 (32.8%) | 11,000 (32.6%) | -71 |
| truth precursors reaching the scorer | 22,604 (67.0%) | 21,055 (62.4%) | **-4.6 pp** |
| wall | 2:02:11 | 2:03:56 | +1.5% |
| peak RSS | 76.5 GiB | 78.3 GiB | +2.3% |

Pass 1 alone: 9,016 against the baseline's 9,095. The retention-time chain
reproduced exactly -- seed p95 23.6 s (1.7% of the run), map from 565,808
anchors at p95 58.5 s, converged after 2 refine rounds at a 14.6 s median.

**The tau-inheritance fix is correct and costs a little.** Making pass 2
calibrate its own threshold instead of inheriting pass 1's turns out to be
STRICTER: 4.6 points fewer known-present precursors reach the scorer, 86 fewer
identifications, and 0.6 pp more entrapment FDP. It is still the right
behaviour -- a threshold calibrated on pass 1's wide-window statistics has no
business gating pass 2's narrow-window ones -- but it is a correctness fix, not
an improvement, and it should be reported as such.

## Gate C is NOT broken. My overnight reading of it was the artefact both reviewers predicted.

The run measured what the 98%-ballast fixture could not: survival by whether the
precursor is actually PRESENT, using DIA-NN's 33,749 confident precursors as the
present set.

```
  known-present (DIA-NN truth)  21,055 / 33,749   62.4%
  ALL target precursors        731,448 / 4,991,901 14.7%
  decoy precursors             708,133 / 4,625,804 15.3%
```

Decomposed against codex's model, `P(target passes) = (1-pi)*q0 + pi*q1`, with
prevalence pi = 0.68%:

```
  q1 present-target sensitivity   62.4%
  q0 absent-target admission      14.4%   (solved from the aggregate)
  decoy admission                 15.3%
  predicted aggregate             14.7%   observed 14.7%
```

**The gate enriches present precursors over decoys 4.1x.** The overnight
headline -- "targets admitted 16.0%, decoys 16.5%, the gate separates nothing" --
was exactly the artefact kimi and codex independently predicted: on a library
that is 99.3% absent, the aggregate target rate is q0 plus a rounding error, and
q1 is invisible in it. Equality there is what a WORKING gate looks like.

**What survives, and it is the real cost: the gate discards 37.6% of
known-present precursors before anything scores them.** That is a genuine
sensitivity loss and it is the number to attack -- but it is a trade, not a
malfunction, and it cannot be judged without an FDP that means something.

## What is still true from the night

- **alpha does not deliver its stated rate.** 0.05 nominal, 15.3% decoy
  admission measured here (16.5% on the fixture). tau is fixed from the first
  `gate_calibration_n` decoys and precursors arrive in retention-time order, so
  the calibration sample is the earliest eluters. The procedure is broken even
  though the gate is useful.
- **The FDR is under-calibrated.** 12.36% entrapment FDP at a claimed 1%.
- **Extraction is sound** (doc/40): our traces are cleaner than DIA-NN's and our
  apexes agree with its to a median of 0.0 s.

## A limitation of -gate_log, found using it

The log records the precursor INDEX into the library as loaded, and that index
cannot be mapped back. Reconstructing the documented sort (m/z, charge, decoy,
sequence text) agreed with the log's own decoy column for **49.1%** of rows --
chance, because the arena's sequence string is not the parquet's
`Modified.Sequence`. So the log can report rates but cannot answer "which
precursors", which is the question that matters.

Fix before the next use: write sequence + charge + decoy, not the index. The
measurement above had to be recovered from the output TSV instead, which works
only because a gate-rejected precursor produces no candidate.

## Assessment

The night's central recommendation -- default the gate off -- was **wrong**, and
this run is what would have shown it. Reverting it before the run was right.

The defensible items are unchanged and all of them are calibration, not gating:
apply the measured 3.62 ppm fragment window (pending Astral), fix the tau
calibration sample so alpha means what it says, and report entrapment FDP beside
the q-value so any future change can be judged at matched empirical FDP rather
than at a nominal 1% that is really 12%.
