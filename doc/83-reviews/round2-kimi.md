  # Q2 — THE ORACLE-vs-NATIVE GAP (+3.57)

  Mechanisms ranked, all from the pasted code:

  1. **[HIGH, BITE] Extreme-prior Newton steps → the saturated regime.** Base score = logit(training prior) (gbt.h:302-304); at the measured ~1:155 per-fold prior, an early pure-positive leaf has hessian ≈ p(1−p) ≈ 0.006/row and an unbounded Newton step ≈ 1/p ≈ 160 (`max_delta_step` default 0, gbt.h:83-87). This is arithmetically the measured DScore 75-165 saturation and explains why the leaf cap restored seed 43 and why `intercept_zero` halves the step (gbt.h:88-90). Mechanism #1 by a wide margin. VERIFIED in code; the magnitude claim is INFER from the gbt.h:89 comment's own arithmetic.
  2. **[HIGH, BITE] Per-iteration bin-edge recomputation (fixed_bins=false default, gbt.h:268-277).** The loop re-selects positives every iteration, so every re-selection re-discretises *every* column — the measured amplification where a pure-noise column moved IDs 11.9% (gbt.h:99-105; NULL_CONTROL, `PeakGroupScorer.h:331-341`). A fold-seed change alone can flip the regime through this path with no evidence change. One flag, already implemented, never the default.
  3. **[MED, BITE] Unguarded positive-set churn.** Offline replay measured 11-36% churn per iteration with IDs still rising (lda.h:179-185); `stop_on_composition` exists but defaults false (lda.h:171) and is CLI-gated (OpenDIAlyzer.cpp:4442). n_iter=3 fixed regardless of convergence.
  4. **[MED, BITE] Fold-scale pooling.** `normalize_folds` (default true) rescales by each fold's own decoy null (lda.h:1350-1363); a saturated fold's null compresses its top (w1_ctl70 fold 1: 0.75×, lda.h:194-199), so the pooled head is partly sorted by fold. `fold_pool_rank` (v1.13) fixes exactly this and defaults off (lda.h:194). Whether the reference arm ran it is not in the pasted record — INFER it did not.
  5. **[MED] No monotone constraints on the shipped engine.** `nonpositive_features` clips LDA weights only; the comment admits it "protects the non-default path" (lda.h:930-935). DIA-NN's `check_weights` analogue is absent for GBT. RT_DELTA was removable partly because of this gap (`PeakGroupScorer.h:130-131`).
  6. **[LOW] Positive-label contamination is inherent** to semi-supervision (train_fdr 0.15/0.05, lda.h:1163-1166); the oracle's advantage here is unreachable. Do not chase.
