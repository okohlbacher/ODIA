# State of play, 2026-08-28: calibration, and what the counts can bear

Twenty-one arms on S08 at 500,000 precursors, two adversarial reviews of the
conclusions and two of the plan. The headline is not a result but a
**measurement of this project's own resolution**, and most of what was reported
in the last 24 hours does not clear it.

## 1. The jitter band, and why every count below is quoted against it

Changing the PINNED fragment mass offset by 0.0004 ppm -- a change that prints
IDENTICALLY in the log's three decimals -- moves identifications:

    offset        pass 1   pass 2   MSE removed
    -10.0206         845    1,270      57.4%
    -10.0210         749    1,172      56.6%
    -10.0214         763    1,271      55.1%

**Band: 99 identifications, 8.4%.** The counts SCATTER rather than drift
(845/749/763), which identifies the mechanism: the q <= 0.01 operating point
rests on 6-10 decoys, so one tail decoy moves the count 12-17%.

This is not non-determinism. Determinism is established more strongly than
before: `m6_base_s1` (96 threads) and `j9_mid` (48 threads), run hours apart
under different load, agree in every column; `w7_apply_base` reproduced
`i5_base` with a BYTE-IDENTICAL score table (md5 `d18b09a743cdc5a8903b0808e28661
53`); `x8_imfix_wide0` reproduced `i5_imfix` exactly despite reaching the same
mass regime by a different CLI route. The map is exactly repeatable AND steeply
sensitive.

**`m6_base_s1`'s 1,172 is the BOTTOM of its own band.** The cell's central value
is ~1,238. Every effect measured against it is inflated by ~66 identifications.

`removed: X%` (out-of-fold squared 1/K0 error) spans 55.1-57.4% across the same
three arms -- **a band of 2.3 points**, against 8.4% for the count. It is the
robust readout, and that is now measured rather than asserted.

## 2. What actually survives

**AMENDED, 2026-08-28 12:05 -- the effect is real, the MECHANISM was wrong.**
Widening pass 1's mobility window was reported here as improving the
calibration, out-of-fold MSE removed 56.6% -> 67.1%, "+10.5 points against a
2.3-point band, 4.6x". The comparison was not single-factor: charge 3 crosses
its 120-anchor floor inside it, 106 -> 157, so the window widened AND a
per-charge gate flipped. Holding the flip fixed (`-im_min_anchors_per_charge
200`, so charge 3 stays uncorrected in both):

    arm             pass 2   MSE removed   charge 3
    n_s1            1,172       56.6%      106 anchors, NOT APPLIED
    n_s2_floor200   1,276       53.9%      157 anchors, NOT APPLIED
    n_s2            1,330       67.1%      157 anchors, constant

    window effect    = +104        gate-flip effect = +54     (sums to +158)

The identifications split 2:1 toward the window. The CALIBRATION result inverts:
with charge 3 uncorrected in both arms, widening pass 1 made out-of-fold MSE
removed **WORSE**, 56.6% -> 53.9%. The +10.5 points is charge 3 being CORRECTED
(53.9% -> 67.1%), which the wider window enables only by harvesting enough
anchors to cross the floor.

So the binding constraint is plausibly the FLOOR, not the truncation, and
`doc/36` section 5c already records that "min_anchors_per_charge = 120 is not
defensible as a single gate". `run_floortest.sh` asks the complementary question
-- narrow window, floor lowered to 100 so charge 3's own 106 anchors are
admitted -- which would be a far cheaper intervention if it recovers the effect.

The out-of-fold MSE remains the robust READOUT (band 2.2-2.3 points across four
arms); what changed is which factor it was crediting.

  **WITHDRAWN from this entry, 2026-08-28:** "the measured CCS->1/K0 coefficient
  error moves -3.4% -> -5.1%". That gloss is not a measurement and doc/36
  section 5a ordered it struck on 2026-08-18. If the slope were a pure
  multiplicative scale error the correction at the pivot would be slope*pivot --
  -0.0245 at 0.991 gives -0.0243, where the same fit logged +0.017. The fitted
  slope is `c*lambda_z`, shrunk by the charge's own reliability ratio. The gloss
  was still being PRINTED by the engine, so it was read off the log and quoted
  here as support for a new conclusion; it is now removed from the log too.

  Two further caveats stand. The -4.66% "untruncated" reference is circular: it
  was fitted against DIA-NN's observed mobilities, and the affine coefficient
  0.95323 corresponds to -4.68% because it was BUILT from that fit. And the
  x1 -> x2 comparison is not single-factor -- charge 3 crosses the 120 floor
  inside it -- which `run_floorsep.sh` is measuring.

  What survives unaided is the out-of-fold MSE: +10.5 points against a 2.3-point
  band. That number needs no gloss and no external reference.

**VALIDATED. The mass-gate fallback is expensive, and its cost splits.** Forcing
the raw library through each regime:

    10 ppm @ -10.021    1,172      (band 1,172-1,271)
    50 ppm @ -10.021      886      breadth alone      -286
    50 ppm @  0           669      + mis-centring     -217

Breadth is the larger term but mis-centring is 43% of the damage. Both are far
outside the band.

**CLEARED, byte-exact.** `-mass_width_from_ids apply` is a strict no-op where the
mass gate passes: `w7_apply_base.tsv` is byte-identical to `i5_base.tsv`.

**NOT ESTABLISHED. Everything about the affine library correction.** The
four-cell table:

    pass-1 window     raw        affine
    x1 (0.025)        1,172      1,347
    x2 (0.050)        1,330      1,238

Both simple effects (+175, -92) are 1-1.8 band widths, measured against a
baseline that drew low. The interaction (267) was chosen after seeing the
result, and its own noise is ~sqrt(2)x99 = 140, so it is under 2x. The x1->x2
comparison is ALSO not single-factor: charge 3 flips NOT APPLIED -> APPLIED
across the 120 floor inside it.

## 3. Two couplings nobody had documented

**The fragment MASS calibration reads the LIBRARY's 1/K0.**
`MassCalibration.cpp:998-1001` rejects a probe peak unless
`|peak_im - library_im| <= 0.010`. The affine displaces 1/K0 by +0.0224 at
1/K0 1.0, putting **79.06% of 500,000 targets outside the probe**; the mass
statistic degrades 0.186 -> 0.252 and the gate fails. So editing a library's
mobility column silently starves the mass calibration -- and it contaminates
every mobility arm above, because "raw vs affine" is also "probe intact vs probe
cascade".

**Narrowing the fragment window starves the MOBILITY gate's control.** A
+/-8.86 ppm window left 15 control residuals against 40 and 152 in the wider
arms. `peakednessRatio` returns a 1e9 SENTINEL when its denominator is zero, and
the gate compared against it, so it could only refuse.

## 5. My errors, this cycle

Thirty of the project's forty retracted claims made a change look better
supported than it was. This cycle continued the pattern:

1. "One factor differs: the library's IM column" (doc/72). Two differed.
2. "The -34.7% is confounded." It is MEDIATION -- the total effect is real.
3. "0.252 vs 0.25 is a knife-edge accident." The corpus separates cleanly:
   209 passes <= 0.236, 7 failures >= 0.252. The treatment moved the ratio 0.066,
   33x the overshoot.
4. "The threshold sits inside the bulk, not in a gap." It sits in a gap.
5. "Wide window -> more candidates -> more interference." Pass 1 has the same
   window asymmetry and produced FEWER candidates with a WORSE deficit.
6. "Make `-mass_width_from_ids apply` the default." The disproof was already in
   this repo in three places: Astral 4,969 -> 2,422.
7. "One Astral arm validates an ion-mobility default." Astral has no mobility.
8. "The best cell is raw+x2 (1,330)." affine+x1 is 1,347.
9. "Affine hurts once truncation is fixed." Inside the band.
10. "MSE-removed is threshold-free." True, but asserted; now measured at 2.3pts.
11. Edited a running shell script and killed the batch that carried the control
    everything depended on.
12. Reported "all 52 tests pass" twice to justify code changes, while a third of
    the suite was not configured.

## 6. Plan, as ranked by two independent reviews

Both put **P3 first** and both name the same missing workstream.

**P3. Key the fragment-mass probe on the calibrated axis, not the library's.**
It is a live correctness defect that contaminates the evidence base for
everything in section 2. Add a metamorphic invariance test: a library IM edit
must not change the fragment-mass gate outcome.

**P0 (not previously on the list). The candidate-generation funnel audit.**
Both reviewers flag that P1-P5 are all downstream of proposals that already
exist. The prior leading defect was that ODIA fails to PROPOSE peaks DIA-NN and
OpenSWATH both find. Take the consensus set, and for every reference precursor
record survival through enumeration, extraction window, chromatogram, proposal,
anchor admission, scoring, gates, pass 2, FDR -- with **proposal recall before
scoring** as the primary outcome, stratified by |peak_im - library_im|. That
directly tests whether truncation bites at the proposal stage (large) or only at
scoring (small). Note that P3 was itself a proposal-layer coupling found by
accident.

**P2. Fit the MS1 mass axis independently.** Every gate-failing arm logs
"MS1 mass axis centred on 0.000 ppm (borrowed from the fragment fit); median
residual 3.398 ppm -- FAR FROM ZERO". DIA-NN calibrates MS1 separately and its
corrections differ by 3.4 ppm on this exact file.

**P4/P5. Hygiene with teeth.** Two doc/36 retractions still live in the code
(a mislabeled CCS gloss; an assertion that a slope is shared across charges when
it spans 28%) -- check whether anything RELIES on the shared-slope claim before
deleting. `-use_pi0`, `-train_fdr_initial`, `-train_fdr` are registered, parsed,
stored and never read; make non-default use fail loudly.

**P1. Do NOT change the `-im_window_pass1_scale` default.** Recast as a
multi-file validation programme: paired x1/x2 on several held-out **timsTOF**
files, per-charge breakdown, entrapment FDP, runtime and memory. The
justification should run from the physics -- a -4.66% slope error at 1/K0 ~ 1.0
wants a half-window ~0.047, so 0.050 is what the instrument asks for -- with the
count as confirmation, not the other way round.
