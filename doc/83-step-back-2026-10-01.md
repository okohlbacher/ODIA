Maps to F02. Trap: budget under-counting (sibling booked 160 B/peak vs 44 measured; ODIA's knob covers 5 planes only, RSS/budget 1.27-2.11x).
4. **Store one degree of freedom per point.** Trace 120 B + 12 B/pt → 20 B + 4 B/frame: 35.6 → 7.3 GB, digest identical (`DX/docs/TRACE-STRUCT-REDESIGN.md:6-22,44-55`). → ODIA: two of five planes are copies (F03); MS1 is dense 1,343 bins/row where each row is read in a 444-584-bin span (F12). Maps to F06(b)/F09. Trap: any `MALLOC_*` env var freezes the dynamic mmap threshold at 128 KiB unless `MALLOC_MMAP_THRESHOLD_` is set too; doc/10 set it to 128 KiB deliberately (`D/10:254-257`, `MALLOC_MMAP_THRESHOLD_=131072`), so its −11%/+16% measures that threshold, not glibc's dynamic default — the F09 arm uses 32 MiB.
6. **Thread-count invariance is the acceptance gate; order-dependent shared state is how "output-identical" fails.** threads 8 == threads 100 byte-identical after fixing (`DX/CHANGELOG.md:1192-1195`); count equality is weak (identical count, 2,730 membership churn, `RUNTIME-PLAN:86-95`). → ODIA is byte-deterministic across thread counts BECAUSE the sink is serial (`M/odia-is-deterministic.md:34-46`; md5 16 vs 64 `D/BACKLOG.md:2040-2042`); a parallel sink must commit Gate C admission, `mass_anchors` order/cap and group order in emit order (F04).

Consistent with `M/odia-memory-is-the-problem.md:25-28`.
