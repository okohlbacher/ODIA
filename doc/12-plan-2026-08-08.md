# Plan, 2026-08-08: stop refining the evidence, raise the prior

Written after an adversarial review that refuted three of my own claims and
found a heap over-read in code whose results I had already reported. This plan
supersedes the working direction of 2026-08-06/07, which was wrong.

## 1. What the original plan said, and where we actually are

`doc/02-decisions.md` D1: *"Determinism and phase instrumentation are therefore
preconditions, not deliverables."* D2: Phase 1 is the library. D10: Phase 2 is
extraction, *"Scoring is Phase 3."*

`doc/07-scoring-plan.md:88-96` fixes Phase 3's internal order:

1. peak-group detection and honest sub-scores
2. **cross-check those sub-scores against OpenSWATH on the same input**
3. classifier and q-values
4. **entrapment before believing any q-value**

Status: 1 and 3 done. **2 has never been done.** 4 was built out of order and
its fixture plants a 33% true-positive rate against a real 1.5% — so it does
not model the regime it exists for.

Also unbuilt, and both were called preconditions:

* **D1's determinism harness.** Partly discharged tonight: the extract-score
  pipeline is bit-identical across a 4x thread change (see BACKLOG). Library
  generation, ONNX and permutation invariance remain unmeasured.
* **D10's mzML reference source.** *"an mzML implementation is not a detour: it
  is the reference the mzPeak implementation will be checked against, value for
  value."* `MzPeakSource` is still the only `SpectrumSource`, so no reader bug
  can be distinguished from an extractor bug.

## 2. The drift, stated plainly

The 1.5% true-positive-rate collapse was measured at 17:03 on 08-07, and the
document immediately recorded the rule: a library built from the comparator's
confident set is a RANKING benchmark, a proteome-scale library is a SEARCH
benchmark. **Every measurement taken in the five hours after that ran on a
ranking benchmark**, on a subsystem — ion mobility, then fragment mass — that
cannot change the headline number. Deltas: +67, -17, -65, -20, and a -2380 that
turned out to be undefined behaviour.

The mobility work was not worthless (the slope is real, if smaller than fitted)
and the mass-calibration diagnoses are correct (the latch, the wrong-RT probe,
the uninformative control are all genuine). **Correct work on the wrong
subsystem is still drift.**

## 3. What the review changed

| claim | verdict | consequence |

| feature COUNT is the lever | **refuted** | the cliff was an artefact of independent draws; correlated features give 0 at 4..110 alike |
| batching is refuted | **not established** | the probe scored a subset in isolation; DIA-NN trains on one and scores all |

The single most important correction: **the lever is ORTHOGONALITY, not
count.** Fifteen sub-scores that all read MS2 fragment traces fail together when
an interferent co-elutes. Adding more of the same buys nothing — measured.

## 4. The plan

### A. Raise the prior — build `doc/08`'s prefilter  (the critical path)

At a 1.5% prior, 1% FDR demands a likelihood ratio near 6500:1. Every scoring
improvement pushes on the numerator. **A prefilter changes the prior itself,
and the required ratio falls with it.**

`doc/08-prefilter-design.md`, written 08-04 and then forgotten, already contains
the measurement: unconditioned fragment match depth separates **729.7 against
0.39 true identifications per thousand — 1,800x from one quantity**, where
ODIA's conditioned `fragment_coverage` is flat at 16-29. It is fully designed,
including the three safety rules (equal counts not equal thresholds; k-fold
cross-fitting against the scorer; report the discarded fraction).

It also emits `best_spectrum_rt`, which breaks the cascade poisoning everything
else: pass 1 identifies nothing → no RT map → pass 2 extracts at the wrong times
→ the mass probe matches noise. One build fixes the prior AND the RT seed.

**Judge on `v6_50k` only**, in true identifications per thousand retained.

### B. Add MS1 — the only orthogonal evidence available

Survives the feature-count correction, on better grounds than before: not "more
columns" but a second measurement with an independent failure mode. S08 carries
1,343 MS1 spectra at ~1.8 s. Plan unchanged in BACKLOG. DIA-NN uses MS1 in
DETECTION, so it may also cut into the 9,890/19,150 no-candidate precursors.

### C. Finish the instrument

1. **Split Astral's 9,890 four ways** — no chromatogram / picker rejected /
   scorer dropped / ID unmatched. All four are already in the run. Costs one
   grep and settles where the 47.6% actually goes.
2. **A 1.5% case in the entrapment fixture.** It plants 33% today, so it
   certifies q-values at 20x the wrong prior — including the "+0.90 at a
   matched 1.00% entrapment rate" that the mobility work is documented by.
3. **The OpenSWATH cross-check**, `doc/07` step 2, never done. Two sub-scores
   have already been found worthless (`USABLE_FRAGMENTS` constant 12.000 for a
   week; `IM_DELTA` all-NaN) — exactly what step 2 exists to catch.
4. **Expose the learned model** from `scoreSemiSupervisedLDA` so batching can be
   tested honestly: train on a batch, score the full set, q on the full set.

### D. Park, do not delete

The mass calibration. Four commits deep on a correction that is disabled, on a
file that cannot show the headline problem. Both fixes are in the tree behind
flags and both lose identifications. Revisit only once (A) has given pass 1
something to fit an RT map from — which is the precondition the subsystem was
found to be missing.

Also park: an attenuation-corrected (Deming) mobility slope. Real, small, and
not on the critical path.

## 5. Order

C1 (one grep) → C2 → **A** → B, with C3 and C4 folded in as they gate.

The test of this plan is not an identification count on `lib_targets`. It is
**true identifications per thousand retained on `v6_50k`**, where the current
answer is zero.
